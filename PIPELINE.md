# Pipeline Description

## Processing Pipeline

Дані проходять через такі етапи:

1. Читання записів із JSON або JSONL файлу.
2. Перетворення сирих словників у доменні об'єкти ExchangeRate.
3. Відкидання невалідних записів.
4. Видалення дублікатів.
5. Збір статистики обробки.
6. Виведення результатів через CLI.

Схема конвеєра:

read_rows/read_jsonl_lazy
        ↓
to_exchange_rate
        ↓
valid_rates
        ↓
deduplicate
        ↓
collect
        ↓
CLI

## Статистика конвеєра

Під час виконання збираються такі показники:

- read — кількість прочитаних записів;
- invalid — кількість невалідних записів;
- duplicates — кількість знайдених дублікатів;
- kept — кількість записів після обробки;
- by_asset — статистика за типами активів;
- rate_min — мінімальний курс;
- rate_max — максимальний курс;
- rate_avg — середній курс.

## Batch Processing

Для обробки великих наборів даних використовується функція batched().

Приклад:

count = sum(
    1 for _ in batched(pipeline, 500)
)

Результат для набору даних з 200000 записів:

Пакетів по 500: 400

## Lazy vs Eager Processing

Лінивий варіант використовує генератори та обробляє записи по одному.

Жадібний варіант створює проміжні списки та завантажує всі дані в пам'ять.

Результати вимірювань:

Генераторний конвеєр:
- 154135 записів
- 2.96 с
- 37.4 МБ

Intermediate lists:
- 154135 записів
- 3.23 с
- 140.5 МБ
